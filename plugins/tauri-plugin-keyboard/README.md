# tauri-plugin-keyboard

Reflect's iOS webview input tuning plus the app's single haptic. Despite the
name, no keyboard state crosses the bridge anymore: the webview is pinned and
keyboard avoidance is derived from `visualViewport` on the web side, so the
plugin's keyboard work is native-only tuning (`ios/Sources/KeyboardPlugin.swift`):

- pins the webview scroll view so the system keyboard cannot shove the page,
- removes the form-assistant accessory bar above the keyboard,
- lets deliberate programmatic `focus()` calls raise the keyboard,
- exposes one command, `impact_light`, because WKWebView has no
  `navigator.vibrate`.

Mobile-only: `apps/desktop/src-tauri` depends on this crate for iOS/Android
targets only and registers it under `#[cfg(mobile)]`. Android has no
implementation yet and fails the build on purpose (`src/mobile.rs`).

## Layers

| Layer | Path |
| --- | --- |
| Rust crate (command routing, desktop stub) | `src/` |
| Swift implementation | `ios/Sources/KeyboardPlugin.swift` |
| TypeScript bindings | `packages/core/src/ipc/keyboard-plugin.ts` |

## Changing the command surface

Adding, renaming, or removing a command must update, in the same PR:

1. `src/lib.rs` (`generate_handler!`), `src/commands.rs`, `src/mobile.rs`,
   and the `src/desktop.rs` stub;
2. the Swift `@objc` method in `ios/Sources/KeyboardPlugin.swift`;
3. `build.rs` `COMMANDS` (then run a build once so
   `permissions/autogenerated/` regenerates, and commit the diff);
4. `permissions/default.toml`;
5. the capability mount in `apps/desktop/src-tauri/capabilities/mobile.json`;
6. the TS binding in `packages/core/src/ipc/keyboard-plugin.ts`.
