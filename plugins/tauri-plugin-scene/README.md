# tauri-plugin-scene

The iPad window scene's traits, as iPadOS apps lay out by them. Today that
is one command, `size_class`, and its `sizeClassChanged` event: UIKit's
horizontal size class of the window. A regular-width iPad window renders the
desktop workspace; a compact one (Slide Over, a narrow Split View pane, a
small Stage Manager window) renders the phone shell. The CSS width alone
cannot say where iPadOS draws that line, so the answer comes from UIKit.

iOS-only: `apps/desktop/src-tauri` depends on this crate for the iOS target
and registers it under `#[cfg(target_os = "ios")]`. Android has no size
classes and fails the build on purpose (`src/mobile.rs`).

## Layers

| Layer | Path |
| --- | --- |
| Rust crate (command routing, desktop stub) | `src/` |
| Swift implementation | `ios/Sources/ScenePlugin.swift` |
| TypeScript bindings | `packages/core/src/ipc/scene-plugin.ts` |
| App service | `packages/app/src/app/size-class-service.ts` |

## Changing the command surface

Adding, renaming, or removing a command or event must update, in the same PR:

1. `src/lib.rs` (`generate_handler!`), `src/commands.rs`, `src/models.rs`,
   `src/mobile.rs`, and the `src/desktop.rs` stub;
2. the Swift `@objc` method or `trigger` call in `ios/Sources/ScenePlugin.swift`;
3. `build.rs` `COMMANDS` (then run a build once so
   `permissions/autogenerated/` regenerates, and commit the diff);
4. `permissions/default.toml`;
5. the capability mount in `apps/desktop/src-tauri/capabilities/ios.json`;
6. the TS binding in `packages/core/src/ipc/scene-plugin.ts`.
