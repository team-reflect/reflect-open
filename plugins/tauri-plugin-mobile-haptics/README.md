# tauri-plugin-mobile-haptics

Reflect's haptics: one command, `impact_light`, the app's single haptic
strength. It exists because WKWebView has no `navigator.vibrate`, so JS
cannot fire haptics on its own. Split out of `tauri-plugin-keyboard`, which
is pure webview tuning now. The `mobile-haptics` name keeps the crate
distinct from the official crates.io `tauri-plugin-haptics`, a different,
unrelated implementation.

Mobile-only: `apps/desktop/src-tauri` depends on this crate for iOS/Android
targets only and registers it under `#[cfg(mobile)]`. Android has no
implementation yet and fails the build on purpose (`src/mobile.rs`).

## Layers

| Layer | Path |
| --- | --- |
| Rust crate (command routing, desktop stub) | `src/` |
| Swift implementation | `ios/Sources/MobileHapticsPlugin.swift` |
| TypeScript bindings | `packages/core/src/ipc/mobile-haptics-plugin.ts` |

## Changing the command surface

Adding, renaming, or removing a command must update, in the same PR:

1. `src/lib.rs` (`generate_handler!`), `src/commands.rs`, `src/mobile.rs`,
   and the `src/desktop.rs` stub;
2. the Swift `@objc` method in `ios/Sources/MobileHapticsPlugin.swift`;
3. `build.rs` `COMMANDS` (then run a build once so
   `permissions/autogenerated/` regenerates, and commit the diff);
4. `permissions/default.toml`;
5. the capability mount in `apps/desktop/src-tauri/capabilities/mobile.json`;
6. the TS binding in `packages/core/src/ipc/mobile-haptics-plugin.ts`.
